# Planche — revue de sécurité du 08/11/2026

Périmètre : tout le code applicatif de `planche/` (backend Rust `src-tauri/src`, plugin Android `plugins/planche-storage`, projet Android généré `gen/android`, interface React `src/`, configuration Tauri), les workflows GitHub et les dépendances. Lecture complète du code, vérification de chaque constat dans les sources (y compris celles des crates et paquets concernés). Aucun fichier modifié.

Les points corrigés lors de la revue du 25/10/2026 ([SECURITE.md](SECURITE.md)) ont été re-vérifiés : **ils tiennent tous** (CSP, assainissement HTML à l'impression, extraction d'archives bornée, suppression de `write_text_file`, cadre EPUB sans scripts, SQL paramétré, coffre chiffré).

## Constats

Gravité : la probabilité et l'impact pour un lecteur qui ouvre des fichiers et des catalogues **non fiables**. « Après injection » = exploitable seulement si un script hostile tourne déjà dans l'interface, ce que la CSP empêche aujourd'hui (défense en profondeur).

### Information (pas de vulnérabilité exploitable, à connaître)

- **SSRF par conception** : un flux OPDS peut faire requêter `127.0.0.1`, `10.x`, `169.254.169.254` par le backend ; les identifiants ne partent qu'à l'origine du catalogue. Acceptable pour un lecteur de bureau visant Komga/Kavita en LAN ; à noter dans SECURITE.md.
- **Zéroïsation absente** : `chacha20poly1305` sans la feature `zeroize`, clés hex et image en clair non effacées en mémoire. Portée très faible (la base vit en clair en mémoire, limite documentée).
- **TLS Android** : vérification active (rustls + racines Mozilla, aucun `danger_accept_invalid_*`), mais une AC installée par l'utilisateur (serveur LAN auto-signé) est ignorée ; `rustls-platform-verifier` honorerait le magasin Android.
- **Worker pdf.js hors CSP** (Tauri n'émet la CSP que pour les `.html`) : sans conséquence avec pdf.js 6.x (plus de chemin `eval`, pas de `pdf.sandbox`, rendu canvas sans couche de liens). À garder en tête si la couche d'annotations ou le JavaScript des PDF sont un jour activés.
- **`panic = "abort"`** : toute panique d'un décodeur (image, zip, tar, 7z, UnRAR) sur un fichier malformé tue l'application ; combiné au worker de vignettes, cela donne la boucle de #1. Fuzzer `book::open`/`meta::read` sur les quatre formats serait utile.
- **Intents `VIEW` Android** déclarés dans le manifeste mais non traités par le code Rust (fichiers envoyés par une autre app ignorés) : fonctionnel ; si corrigé un jour, passer par `open_file` et refuser `file://`.
- **Dépôt GitHub** : secret scanning et push protection actifs, 0 alerte de secret, 0 alerte code scanning ouverte, aucun fichier de signature suivi par Git (`*.jks`, `keystore.properties`, `local.properties` ignorés).

## Vérifié et jugé sain

- **Puits XSS** : un seul `dangerouslySetInnerHTML` (`Panels.tsx:304`), alimenté par un texte entièrement échappé ; aucun `innerHTML`, `eval`, `new Function`, `window.open`, `href` dynamique ; `t()` ne produit pas d'HTML ; métadonnées de livres, TOC, flux OPDS rendus en texte React ; couvertures OPDS via le proxy backend, jamais de `<img>` distant.
- **`sanitizeBookHtml`** (`print.ts:302-342`) : recréation d'éléments neufs depuis un document inerte, liste blanche de balises et d'attributs, `src` limité à `blob:`, `href` à `#`, suppression avec contenu de `script style iframe object embed form svg math template link meta base`. Aucun contournement trouvé (`<svg><script>`, `<math>`, `<base>`, `srcset`, `formaction`, `xlink:href`, RCDATA).
- **Cadre EPUB** : `srcdoc` sandboxé `allow-same-origin` sans `allow-scripts`/`allow-popups`/`allow-top-navigation`/`allow-forms`, hérite de la CSP du parent ; `allowScriptedContent: false`.
- **CSP** : `'unsafe-inline'` sur `style-src` uniquement (nécessaire, et `dangerousDisableAssetCspModification` cohérent) ; `script-src 'self'` ; `object-src 'none'`, `form-action 'none'`, `base-uri 'self'` ; `connect-src` limité à l'IPC et au protocole `planche`.
- **Protocole `planche://`** : pour `raw` et `page`, le chemin disque n'est jamais tiré de l'URL (clé SQL → `books.path`).
- **Extraction** : `safe_relative`, 256 Mio/fichier, 8 Gio/archive, 100 000 entrées, liens ignorés, tailles vérifiées avant lecture pour RAR et 7z ; `sevenz-rust2` borne ses en-têtes ; UnRAR n'alloue pas sur la taille déclarée.
- **XML** : regex linéaires, aucune résolution d'entités (XXE impossible), un seul niveau d'entités (pas de billion laughs), `meta.rs` borné à 1 Mio.
- **SQL** : 100 % paramétré, les seuls noms de tables formatés sont des constantes ; migrations transactionnelles.
- **Coffre** : XChaCha20-Poly1305, nonce aléatoire par écriture (getrandom), clé 256 bits aléatoire, AAD versionnée, longueur vérifiée avant découpage ; fichier clé `create_new` ; migration qui réécrit bien l'ancienne base par des zéros ; `rollback_journal` correct. **Une défaillance transitoire du coffre système ne régénère jamais de clé** quand `library.planche` existe (`load_key`, `vault.rs:94-127`, trois branches gardées).
- **OPDS** : `http`/`https` seuls ; Basic Auth encodé, envoyé seulement à la même origine, retiré par reqwest sur changement d'hôte/port/schéma ; `user:pass` d'URL retirés ; `Catalog.password` `#[serde(skip)]` ; aucun secret dans les logs ni les erreurs ; dossier de téléchargement fixé par le backend, extension en liste blanche, pas d'écrasement.
- **Capacités Tauri** : `dialog:allow-open` seulement, pas de `fs`/`shell`/`process`/`http` ; `withGlobalTauri` absent ; mobile : trois commandes du plugin + `core:app:allow-exit`.
- **Android** : JNI sain (frames locaux bornés, exceptions effacées, fd détaché à propriété unique, `File` gardé vivant pendant l'usage par UnRAR) ; grants SAF en lecture seule ; `FileProvider` non exporté ; `debuggable`/`usesCleartextTraffic` en debug seulement ; `allowFileAccess`/`allowUniversalAccessFromFileURLs` à `false`.
- **Workflows** : pas de `pull_request_target` ; `secrets: inherit` uniquement sur `push`/`workflow_dispatch` ; les PR de forks compilent sans secrets ; aucun `${{ github.event.* }}` dans un `run:` ; aucune clé dans les artefacts ; publication Store/Play conditionnée par tag + variable + environnement.
